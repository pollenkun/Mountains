# 这个模块还不能替换实际输入锁

`input-claim.swift` 只处理文件和进程身份，不发送输入。现仅接入显式创建的
候选 `InputCoordinator`，还未成为默认实际输入锁。所有入口和结果固定标记 `componentOnly=true`。
组件收据只检验协议，不能证明应用收到输入，或按键已经实际松开。

候选存储格式现为v3，格式编号仍为数字。每轮epoch和所有请求的revision均按十进制字符串传递，
不会经过JavaScript浮点整数。epoch取本轮获取锁时提交后的revision，配合本轮nonce使用。
不再保存有4096轮上限的历史nonce清单；每一轮内的命令和发送者数量仍有限制。
旧轮即使重复使用相同nonce、命令编号和发送进程，也不能操作新epoch。
v1/v2凭据和文件不能静默迁移或重置；生产迁移入口尚未实现。

## 进程消失不再等于可以放锁

登记发送进程时，系统提供 PID、开机编号和出生秒、微秒。
命令先登记，再允许发送程序消费一次许可（`begin`）。
消费记录落盘后才能回复。丢回复仍保留“已经开始”。

登记同时保存结构化原地址：宿主和实际目标的进程代际、窗口编号与边界，
或明确的全局剪贴板、待启动应用地址。登记、允许和开始时都核对原进程尚在。
每个票据后续请求都必须携带完全相同的原地址。收尾时原地址缺失或改变，
会持久保留未知，不能用迟到成功覆盖。这里不存输入文字或剪贴板内容。
窗口地址目前只是已绑定的元数据；真正发送者仍必须核对保留的AX窗口和控件。
这个文件组件没有验证任何实际窗口，也不认证GUI收件。

封住本轮（`seal`）以后，未消费的许可不能再开始。
已经开始的命令必须由原发送进程提交完整收尾记录。
缺记录、记录损坏、仍有按键按下或收尾失败，都不能放锁。
首次失败不能被迟到成功覆盖；冲突记录也会保留失败。

`begin`还须明确声明将创建的剪贴板、焦点恢复责任。按键收尾成功，
不会自动清掉这些跨命令责任。恢复前由原发送进程消费一次`beginRestore`，
核对原地址，剪贴板嵌套恢复必须从内到外；前台与键盘是独立资源，不互相充当外层备份。
所有资源仍一次只准一个恢复写入；实际恢复完成后另写`restorationReceipt`。
恢复许可前同样重新核对原目标进程；目标已结束、换代或查不清时保留原责任，不改发新进程。
封住本轮或控制进程结束后，原发送者仍可按原地址收尾，不能获得新的业务输入许可。
恢复中断、失败、缺回复或换地址都不能算完成，发送者不能退休，旧锁不能释放。
一个命令或恢复正在执行时，另一个输入发送者不能开始。

正常结束时，发送进程须确认旧许可已经退休，或系统确认它已退出。
崩溃接管更严格：原控制进程和所有原发送进程都须退出。
查询不确定就保留旧锁。不会按旧 PID 结束另一个进程。

## 换路径或丢文件不能自动得到空锁

系统文件锁（`flock`）只保护一次短文件事务，不跨越通信和等待。
固定 guard 文件不替换；state 用同目录临时文件、同步、重命名和目录同步提交。
原目录和 guard 的文件身份固定，链接、替换、权限变化、缺文件和坏记录都拒绝。

初始化只能显式用于新建空目录。返回的凭据必须由调用方另行固定。
客户端保存独立冻结副本，调用方修改原对象或返回结果不能更换它。
已有凭据不能重新初始化。组件测试允许任意自有目录；生产入口尚未实现。
删除整套存储、再从无凭据的新客户端初始化，不在这个组件的恢复保证内。

普通同步只支持这里测试的进程崩溃处理，不承诺断电或内核崩溃安全。
私有文件和哈希也不等于对同权限恶意程序的系统隔离。

## 接入实际输入前还要完成这些工作

- 固定同一系统用户共用的持久目录和独立凭据，所有 checkout 共用一把锁。
- 覆盖每个输入发送者，包括 AX、原生辅助程序及其它命令路径。
- v3已保存原目标元数据和实际进程代际，route仍只作随机票据绑定。尚须接发送者的实际窗口、控件与地址核对，不能把元数据相等当作收到输入。
- 登记先于发送命令字节；许可落盘后，再检查取消与命令身份，最后回复允许。
- 实际发送程序每次输入前消费许可；所有 finally 完成后独立落盘收据。
- 鼠标、键盘、剪贴板和退出收尾均有完整记录，不能用键盘记录替鼠标背书。
- `JsonHelper` 现等待异步 `onRecord` 和 `beforePermit`，每次等待后核对本命令、取消及单调时钟期限。两钩子收到本命令的取消信号，必须等待自己发起的全部写入。中断时仍未完成就保留未知和旧锁，迟到完成不能洗白。同步 `onDispatch` 只在实际尝试写ACK后通知，不承担当作持久记录的前置工作。这项接口前提已补；尚未接入这个存储组件，也没有实际发送者独立落盘的收据。
- Web 的 CDP 锁单独验证，不能套用这个原生组件的结果。

发布脚本在开发时生成双架构二进制。两个架构只读同一源码副本。
编译期间仓库源码变化就拒绝发布。运行时只校验并启动打包二进制，不调用编译器。


## 主进程AX调用已接候选，默认入口尚未切换

仅由开发者显式传入已初始化、固定原凭据的 `ComponentInputClaims`，
`InputCoordinator` 才开启这一候选。普通配置、CLI和模型不能开启它。
默认 `nativeCoordinator` 仍使用原锁，既有正式验收门禁继续关闭。

`screen_act` 的每一个直接AX方法现经原 `InputLease` 跟踪。
包括下拉框的首次打开、动态选项、语义点击、右键菜单和明确授权的激活。
每个实际方法各登记一次，不能把AX选择文字和后续JXA输入包成一个发送者。
候选下由真实Node进程登记自己；宿主和目标进程用原AX对象的pid独立查系统出生身份。
未知实际pid不借用宿主，远程面板没有可靠窗口编号时只记录进程，不编造窗口。
新的 `processIdentity` 是固定私有store内的只读查询，不注册目标应用为发送者。
这些元数据不能证明GUI已收到输入，最终结果仍须读回。

完整过程在排队前纳入原lease：登记、许可、开始、真实方法返回、独立写盘收据。
收尾通信离开业务取消范围；实际AX方法始终留在原任务范围。
取消不会丢下正在执行的AX Promise，也不会用取消信号替代实际完成。
开始后才取消，仍收集真实结果并写收据；新动作在发送前拒绝。
已完成的修改可由读回确认，不为了取消而假称没发生。
正常收尾等全部实际调用和记录结束，再封许可、退休Node发送者、释放候选锁。
写盘回复丢失，即使业务代码吞掉错误，也保留原锁并拒绝后续输入。
同lease递归等待AX队列立即拒绝；来自外部的正常并发仍按顺序执行。

候选窗口版本文件共用固定store目录。不同客户端或legacy锁目录不会各存一份版本。
生命周期revision仍只核对协议事务；取得锁、登记发送者不会让自己的窗口快照失效。
本批测试用实际tools调用点、自有文件、Node进程和原生存储程序，AX方法用文件写入替代。
这不是实际桌面输入或焦点证明。键鼠、JXA菜单、AXManualAccessibility启动路径、
剪贴板恢复、全用户共享持久目录、独立凭据和旧版本挡板尚未接齐。
特别是JXA恢复须等在途AX结束，不能先恢复后让AX再改变焦点；该收尾次序仍待后续接线。


## 多个发送程序写记录后，主进程必须重新核对原轮次

辅助程序自己消费begin、写receipt，会推进共享存储的revision。主进程不能继续拿自己的旧缓存去封口或登记下一条。现每次先独立读取固定store，核对最初acquire取得的leaseId、epoch和owner出生身份；不采用辅助程序回包声称的版本，也不能借同nonce换一轮身份。原身份另存冻结副本，不引用可变的返回对象。

原生compare只有在任何修改之前，才回复机器code revision_conflict。主进程仅对有此明确回复的owner文件事务有限重试，最多4次，共用一次5秒单调期限。sender的begin、receipt和retire不重放，丢回复不重试。stage/permit用完尝试后，须独立确认当前票据仍未发放，才能普通报本命令未开始；已permitted/executing或身份不符，仍保留未知。组合动作先前发生的效果不会因此消失。

ComponentInputClaims把绝对期限在入队时交给JsonHelper，业务写入另带取消信号。排队期间到期或取消，先永久关掉本条发送资格，再返回写前拒绝；迟到的队列回调不能启动辅助程序、注册停止监听或发送字节，也不停止前一个正在执行的请求。开始尝试写入后，不能再称未发送；仍等待真实结果或同一进程结束。收尾请求不随业务取消。

这层提前拒绝不是丢下Promise.race：排队条目的未来执行已确定成为无输入的拒绝；已写出的条目不走这个捷径。等待旧请求结束的清理时间可能另需等待，不能把它算成新请求仍可迟到执行。实际写后抛出的同形异常也不会被分类成写前取消。

新增29项检查包含实际Foundation JXA进程直接调用已打包的原生组件，先消费许可、仅写本轮文件、再自行落收尾记录；Node代签被拒绝。JXA故意回旧版本，主进程仍从store正确接续。另用私有文件锁验证真实传输中的排队取消和过期，独立读回确认没有迟到stage。这些检查没有发送键鼠、没有GUI或账户操作。

实际HELPER的启动UI、guard恢复、剪贴板及EOF收尾仍须一起接线。不能只给route ACK挂日志，也不能把此处真实JXA文件流程称为真实键鼠迁移已完成。


## 实际MacPointer先只验证只读启动

当前候选InputLease进入真实MacPointer时，只允许Foundation-only内部ping。它不会加载旧HELPER的Cocoa、NSApplication、窗口、AX、CG、剪贴板或EOF恢复代码。现有legacy helper启动过或eventData已创建的指针对象，不自动关闭或转入候选；候选对象也不退回旧输入。此门禁只保护尚未完成的候选迁移，默认生产流程未切换。

JsonHelper先spawn准确ChildProcess，安装停止监听、超时和close/error处理，再等待专用beforeCommand钩子。InputLease从原生系统查询child出生，登记后逐字段核对sender.birth并再次核对同一child仍活着。这个register没有stage、permit或begin，不授予任何UI输入。父进程登记不能替代JXA自己消费开始许可。

第一条命令写入前再次核对取消、封口、单调期限和原child。登记未完成就中断，仍保留未知与原锁；晚到的回调不写命令、不重启helper。只读ping回复后，整个Promise还继续等待EOF和原进程close。scope从创建就跟踪这段finally；进程强退或收尾未知不能凭ping成功放锁。已结束的原sender由原生系统出生查询核对，不由Node代签retire。

新增36项使用真实MacPointer Foundation进程及自有Node文件夹具，未发桌面输入。普通JXA输入、初始化票据、guard/剪贴板恢复和可复用活helper退休顺序，仍须后续接齐。


## 退出失败不能被普通异常处理洗掉

实际JXA退出时，剪贴板清理与焦点清理分别尝试。前者抛错也不能跳过后者。焦点回执缺失、归因未知或仍未恢复，退出必须失败；明确的人接管保留其新位置。恢复完成只说明资源已收尾，曾抢焦点的后台动作依然失败。

剪贴板恢复先构建原表示并核对BOOL，再复查所有权计数，才清空并写回。writeObjects失败不是成功；原备份与失败保留。失败后EOF不能把自己的clear误认作用户新copy，不能重新尝试后把未知洗白。

实际clip_set现先构造文字和HTML，清空前复查原计数；清空只认该次clearContents返回的计数，不采用后来读取的计数。标记和临时内容一次writeObjects，必须严格返回true。部分写入没有标记时，仅同一个活helper的原备份与固定清空计数可恢复；外部items/count不能替代。用户新copy计数变了就保留用户内容；清空回复丢失则保留未知。新建独立命名剪贴板的真实AppKit往返已测，不访问系统剪贴板。这仍不是独立guardian，也没有解决系统check/write之间任意时刻用户copy的全部边界。

JsonHelper公开stop从创建就纳入当前lease，保留结束未确认的原错误。调用者直接抛出、吞掉、包装或不等待，都不能提前放锁。先前已注册的watch/请求错误收尾走固定private stopChild，scope封口后仍等待原child退出，不给新输入借此绕过封口。InputCoordinator也保留直接收到的未确认终止错误，普通业务失败仍正常释放已清理的锁。

普通JXA接入仍需：初始化前真正读取并保留原焦点、JXA自身begin/finally收据、Node AX完成后才停止所有全局恢复写入，以及实际原发送者提交最终观察。下述文件协议已实现，但并未接通真实界面；字段齐全或最近有硬件输入都不能证明用户接管。


## 前台与键盘焦点必须在所有写回结束后一起核对

每轮最多登记一个UI输入进程（ui_input）。它须在任何输入开始前登记，首次begin必须建立完整焦点组。
Node AX、纯文件或Foundation ping进程分别登记node_ax、file_only；不能将它们伪称真实UI已接入。
现有MacPointer候选ping仍为file_only，候选普通输入仍在发出命令前拒绝。

焦点组绑定同一原发送者、创建命令和scopeId。原前台、原键盘各有独立的原进程出生身份与随机私有引用。
原地址不跟随用户改变；键盘捕获须明确present/absent，present时不能省略键盘责任。
这些值仍由发送者提供；文件组件独立核对进程身份，不核验AX元素或实际前台。

恢复写入只可在封口、全部输入已结束后开始；剪贴板嵌套从内到外，前台与键盘资源没有嵌套次序。
同一时刻仍只准一个恢复写入；一份原进程已结束不能挡住另一份仍有必要的写回。
restored仅表示一次写回结束，不能退休或释放焦点责任。
所有命令均clean/notStarted、非焦点责任也已结束后，原发送者一次提交整组resolveFocus；原组不会半完成。
最终keyboard区分present、absent、unreadable，读失败一律保留未知；初始没有键盘元素也不跳过最终核对。

已经回到原位置时优先认原位置，包括目标本来就在前台的情况。
保留用户当前新位置时，须排除已开始业务的宿主、远程目标和UI发送进程。
不会因某应用只是原恢复目的地、纯文件发送者或仅计划但没开始，就把它排除。
原进程确实结束时，只结束它自己的责任；当前有新目的地也须排除实际业务/UI目标。
应用名地址缺少真实进程时，不能猜测当前位置与业务无关。

最终记录只是资源收尾，绝不代表从未抢焦点或后台任务成功。
此前发生过短暂抢焦点仍须由实际发送者和独立监测判失败。
最终核对后，已认证的矛盾命令/恢复收据仍保留失败，整组转未知；首次最终记录和首次收据保留为历史。
即使UI发送者已退休，另一活发送者的新失败也不能因校验不许保存而丢失。
相同干净旧收据可幂等；不能再次开始恢复，也不能靠好收据或重复旧观察擦掉未知。
详见INPUT-FOCUS-REVIEW.txt。本模块仍不是默认生产锁，20项真机验收尚未运行。
