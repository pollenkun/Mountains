# Computer use 验收记录

## 2026-10-17 更新（Claude）

在 Codex 10-16 的版本上改了下面这些，用户已同意前三项。

- **截图改回持续录屏。** 每个在用的窗口开一路 ScreenCaptureKit 流，录屏期间菜单栏一直有提示。每次取图都等流在请求之后报到，流没动静时补拍一张，不会拿旧画面。每个系统调用都有时限，卡住的调用不再拖住后面的请求。
- **网页后台拖动恢复。** 拖动期间用一个几乎透明、不激活的面板接住一次会话级按下，网页引擎因此读到按键按住；真实鼠标不动，用户的应用收不到按下和松开。授权后的真实鼠标拖动仍保留，用于把文件拖进剪辑软件这类系统级拖放。
- **本机模型不做费用检查。** 本机地址加上价目表里没有的模型，按免费处理（`localModel`）；其他未知价格的模型仍在发请求前拦下。
- **前台授权按应用。** `bring_to_front` 获准后，这个应用留在前台期间，哪个窗口（编辑页、对话框、对话框上的对话框）拿着键盘就可以在哪里操作；应用离开前台即失效。前台和焦点窗口改用 macOS 自己的记录，打开面板（由系统服务进程绘制）时不再误判。
- **用户自己操作不再连累后台。** 动作期间如果用户本人点过或打过字，只算这一步失败，不再关掉这个应用的后台输入。
- **对话框。** 主窗口上的 sheet 不再混在主窗口里编号，读主窗口时会提示去读对话框窗口。系统的 Open and Save Panel Service 进程不再出现在应用列表里。
- **结果更省也更准。** 元素编号在同一窗口的多次读取之间保持不变；动作结果只列变化（+ ~ -），不再附整棵树。像素动作或树里看不出变化的动作，结果直接附当前窗口图。旧截图在请求里只保留最近几张，成批移出，缓存前缀很少变。点击前的像素核对改为目标附近和全窗口各有容差（光标闪烁、时钟不再导致拒绝）。读过窗口之后再读一次，不会让之前的截图作废。
- **报告更诚实。** 元素动作返回 -25205（常见于打开面板）记为“已发送未确认”而不是失败；动作后原窗口关闭或换掉，记为未确认并列出现在的窗口；期望值没达到时写出实际读到的值。
- **规则。** 不许用命令退出、杀掉或重启应用（Flash 曾自作主张杀掉剪映重开）。

#### 实现与平台限制

工具入口为 `packages/computer/src/tools.ts`。读取版本在 `state.ts`、`snapshot.ts`；排队及取消在 `coordinator.ts`、`helper.ts`；输入和截图在 `backend.ts`、`pointer-mac.ts`、`capture-mac.ts`、`native/capture.swift`。

当前真机环境为 Apple Silicon、macOS 26.6.2。截图最低要求 macOS 14.2，因为需要明确排除父子窗口混入截图；没有实测所有中间系统版本。输入仍使用部分 macOS 私有接口，系统升级后需要重跑检查。Windows 和完整 Desktop 界面不在本轮范围。

崩溃留下的输入锁不会超时后自动抢占。因为旧进程可能还在发输入，必须先确认它已经停止。

参考了 [Cua Driver](https://github.com/trycua/cua/blob/main/docs/content/docs/cua-driver/concepts/how-cua-driver-works.mdx) 和 [Peekaboo](https://github.com/openclaw/Peekaboo/blob/main/docs/automation.md) 的目标识别、结果核实和排队方式，没有设为必装依赖。

多窗口按键参考 [Cua 的应用内部窗口切换](https://github.com/trycua/cua/blob/d9998fb4af5d94f784209b0129b9f98c80088d5d/libs/cua-driver/rust/crates/platform-macos/src/input/skylight.rs#L243)。没有采用切前台后再偷偷还原的做法。网页拖动限制与 [WebKit 的按钮状态读取](https://github.com/WebKit/WebKit/blob/main/Source/WebCore/platform/mac/PlatformEventFactoryMac.mm) 一致；这是对本机测试的解释，不是所有浏览器都不能拖动的结论。

HTML 粘贴的 UTF-8 声明也与 [WebKit 的原生剪贴板编码处理](https://results.webkit.org/commit?id=274434%40main&repository_id=webkit)一致；修复效果以本机实际文字和格式检查为准。
